## Project overview

This is a static personal portfolio/landing page for Maksym Soltyk (Soltyk Maksym Yuriyovych), deployed to GitHub Pages at `88Maxwell.github.io`. It is a single HTML page with SCSS styling and a PWA service worker — there is no application JavaScript, no framework, and no test suite.

## Commands

- `npm run dev` — start Parcel dev server on port 8000, output to `__build/` (used for local iteration)
- `npm run build` — clean `build/` and produce a production bundle from `src/index.html` into `build/` with relative public URLs (`--public-url ./`)
- `npm run serve` — serve the contents of `build/` locally as a static site (post-build smoke test)
- `npm run deploy` — publish `build/` to the `master` branch via `gh-pages` (this pushes to the live GitHub Pages site — confirm with the user before running)

There is no lint or test command configured in `package.json`.

## Branches and tooling

- `development` is the source branch (default on GitHub). `master` holds only the built site and is overwritten by `npm run deploy` — never commit source there.
- The bundler is Parcel 1 (`parcel-bundler`), not Parcel 2: CLI flags like `-d` and asset handling follow v1 docs.
- `package.json` `main` points to `/src/js/index.js`, which does not exist; it is unused.

## Architecture

- `src/index.html` is the single entry point (referenced by Parcel via `parcel build src/index.html`). All markup lives here; there is no templating or component system.
- `src/sass/index.scss` is the stylesheet entry point and only does `@import`s, in this order: `variables` → `keyframes` → `global` → `mixins` → `blocks/app`, `blocks/profile`, `blocks/logo`, `blocks/contacts`, `blocks/record`. When adding styles, follow this same import order (variables/mixins before the blocks that use them).
- `src/sass/blocks/*.scss` follow BEM naming (e.g. `.profile__panel`, `.contacts__social`, `.record__label`) matching the class names used directly in `index.html`. Each block file corresponds to one BEM block used in the markup.
- `src/sass/variables.scss` centralizes the color palette (`$primary`, `$success`, `$danger`, `$link`, etc.) — reuse these variables rather than hardcoding colors in block files.
- `src/pwabuilder-sw.js` is a PWA service worker (generated by PWABuilder) that caches all routes with a stale-while-revalidate strategy via Workbox, loaded from `index.html` and registered at scope `/`.
- `src/manifest.webmanifest` and `src/img/cv*.png` provide the PWA manifest and icon set.
- `build/` and `__build/` are generated output directories (from `npm run build` / `npm run dev` respectively) — do not hand-edit files there.
